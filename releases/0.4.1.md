# OKF 0.4.1

This patch release adds Developer ID signing and Apple notarization to macOS release binaries.
The CLI and both agent plugins are version 0.4.1; the OKF document specification remains v0.2.

## macOS distribution

- Both Apple Silicon and Intel binaries are signed with a Developer ID Application certificate,
  a secure timestamp, and hardened runtime enabled.
- Release publication requires Apple to accept notarization for both macOS builds. Missing
  credentials, rejected submissions, and notarization timeouts block publication.
- Signing credentials are used only for release builds on main, imported into a disposable
  keychain, and removed on script exit. Pull-request builds remain unsigned.
- Archives remain `.tar.gz` files containing the signed executable, README, and license.
  Standalone executables cannot have notarization tickets stapled to them; Gatekeeper may
  need internet access to check notarization. Offline first-run verification is not promised.
- macOS deployment target remains 13.0. Previously published unsigned releases are unchanged.

## Upgrade and compatibility

Install 0.4.1 using the standalone installer or download the archive for your architecture.
No document migration is required. Plugins continue to support stable CLI versions
`>=0.4.0, <0.5.0`; CLI commands and document semantics are unchanged from 0.4.0.
Linux releases retain their native musl builds and existing installation behavior.

## Validation

The release workflow checks synchronized metadata, formatting, workspace tests with default
and URL-source features, generated references, and skill workflows. Native builds run CLI
and signed-binary smoke tests before publication. Signing tests cover accepted and rejected
notarization responses, submission failures, and temporary credential cleanup.

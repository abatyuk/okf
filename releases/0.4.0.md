# OKF 0.4.0

This release adds coordinated, recoverable changes to records and fixes inconsistencies found
by a command-by-command audit of the CLI. The CLI and both agent plugins are version 0.4.0;
the OKF document specification remains v0.2.

## Coordinated record changes

New `okf changeset plan`, `apply`, and `recover` commands accept an explicit version 1 YAML/JSON
operation document. Supported operations create and replace concepts, edit frontmatter with
RFC 6902 patches and replace bodies, move concepts, retarget selected consumers, remove files,
and write text artifacts. Splits and merges combine explicit operations and reference mappings;
OKF does not infer which new record a consumer should reference.

- Plans execute on an isolated copy and show complete file diffs plus a baseline digest.
- `apply --expect <base-digest>` refuses a changed baseline. Use the same reviewed operation
  document: this digest guards the baseline, not the plan document itself.
- Preview and publication share path, expected-state, and destination preflight checks.
- The complete resulting bundle must be conformant and introduce no new dangling supported
  local references. Checks include Markdown/artifact links and `file`, `line-range`, and
  `markdown-heading` sources. Existing unrelated broken references may remain; Git, URL,
  producer-specific sources, and unexamined cross-bundle consumers are not checked.
- Publication is atomic per file and journaled for rollback. It is not an atomic snapshot for
  concurrent readers, and transactions write only one bundle.
- `recover` rolls back interrupted uncommitted publication or completes committed cleanup.
  It refuses active publishers and intervening edits, and preserves file permissions.
- CLI mutation handlers coordinate through a persistent bundle writer lock. Transaction
  controls are excluded from bundle discovery. Keep `.okf-transaction.lock` and
  `.okf-transaction/` out of version control; do not manually delete a pending journal.
- Active tool configuration, catalogs, overrides, and ontology sidecars cannot be changed by
  a record change set. Use the existing ontology commands for ontology authoring.

See the README and generated CLI reference for operation syntax and examples.

## Safer mutations and content preservation

- Concept writers use exclusively created temporary files instead of following predictable
  temporary-file symlinks. Concept creation publishes without overwriting a competing create.
- Moves preflight the complete write set and use recoverable publication rather than leaving
  rewritten referrers behind when a destination write fails.
- Moves and retargeting handle self-links, reference-style Markdown, images, bare declared
  references, structured selectors, and curated index/log navigation within the bundle.
- File and text-fingerprint resources retain bundle-root semantics when concepts move;
  Git source resources retain worktree-root semantics.
- Removal guards include structural navigation and declared references. `rm --force` remains
  an explicit way to permit dangling references.
- Section edits preserve unrelated whitespace and fenced content.
- Ontology edits and previews preserve the meaning of YAML scalar values containing hashes
  and literal blocks; comment preservation can no longer duplicate scalar content.
- Add rejects conflicting type assignments and arguments that would previously be silently
  discarded, including incompatible computation/body combinations.

## CLI discovery, queries, and checks

- Help hides scope, revision, and bundle-selection options on commands that do not support
  them. In particular, `show --revision` is not a historical-read feature. Supported historical
  commands remain list, search, graph, backlinks, links, resolve, and affected.
- Schema reports command-specific global capabilities, corrected stdin support, argument
  conflicts/dependencies, aliases, arity, build availability, and new output records.
- Existing option spellings remain available. Ineffective compatibility options and discovery
  failure-threshold aliases receive explicit diagnostics. PDF export is still unavailable and
  now says so clearly.
- Missing concept resolution exits 1. Qualified containing concepts resolve from the correct
  bundle, and structural indexes resolve consistently, including in historical scope.
- Human multi-bundle search includes bundle identity. Projection values and column headings
  agree when projection and display options are combined. Graph roots normalize consistently.
- Artifact listing and browsing block symlink escapes. Bounded UTF-8 output no longer becomes
  binary merely because truncation splits a character. Fetched artifacts honor line selection.
- Computation inspection shares contract validation with lint and no longer labels malformed
  contracts, duplicate parameters, or empty computation fences valid. It never executes code.
- Affected queries include source-artifact dependencies while keeping artifact nodes out of
  the concept graph, including direct, transitive, depth-bounded, and scoped queries.
- Catalog lint respects disabled rules and configured severities for local declared references.
- Doctor inspects the effective ontology sidecar and reports its actual path if missing.
- Diff excludes historical Markdown symlinks consistently with current bundle scanning.
- Ontology inspection includes complete authored declarations, selectors, relationships,
  ancestry, and trust fields. New `ontology field-type list/show` commands expose reusable
  definitions and effective inherited constraints.

## Upgrade and compatibility

This is a minor-version update because observable behavior changes: missing `resolve` results
now fail, unsafe or conflicting authoring requests are rejected, additional broken references
are caught during removal, and multi-bundle human tables include identity columns. Machine
consumers should use NDJSON and inspect schema capabilities rather than infer support from
globally declared options. Scripts that treated a missing resolution as success must handle
exit 1 or inspect its result explicitly.

Update the CLI and plugins together. The 0.4.0 plugins require CLI `>=0.4.0, <0.5.0`, including
the change-set operations referenced by the reorganize workflow. Existing OKF v0.2 bundles do
not require a document-format migration. Cross-bundle write transactions remain unsupported.

## Distribution and validation

Release archives target Linux x86_64/aarch64 with musl and macOS x86_64/aarch64. Published builds
enable `url-sources`; remote retrieval remains explicit. macOS deployment target remains 13.0,
and binaries are not Developer ID signed or notarized.

The release workflow validates synchronized metadata, distribution tests, formatting, workspace
tests with default and network-enabled features, generated references, and agent skill workflows.
Each native platform runs CLI tests and a packaged-binary smoke test before publication. Assets
include all four archives, `SHA256SUMS`, and the standalone installer.

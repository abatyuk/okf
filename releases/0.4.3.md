# OKF 0.4.3

This release adds consistent frontmatter ordering and automatic lint fixes, reduces
repeated Git reads, and improves local macOS builds and cross-repository skill guidance.
The CLI and both agent plugins are version 0.4.3; the OKF document specification remains v0.2.

## Changes

- Concept writes put `type` first, followed by ontology fields in declaration order,
  reference-only keys, then undeclared keys in their existing relative order. Ordering
  applies recursively to declared objects and list items. Without a matching ontology
  type, only `type` moves first. Read-only inspection retains authored order.
- The new `frontmatter-order` lint warns by default. `okf lint --fix` normalizes affected
  concepts and reports remaining findings. Values, list order, body text, and verification
  metadata are preserved; YAML comments and scalar presentation may normalize.
- Git-backed graph queries, historical reads, and source fingerprinting reuse discovery
  and object reads within a command and batch repeated work. Caches expire between
  commands, including failed lookups; examination scope and per-source results are retained.
- On macOS outside CI, `cargo xtask build` and `cargo xtask install` ad-hoc sign and verify
  local Mach-O executables. Published macOS binaries continue to use Developer ID signing
  and Apple notarization.
- Skills explain frontmatter ordering and distinguish qualified CLI targets from authored
  path-based links, with a worked example spanning separate repository checkouts.

## Upgrade and compatibility

No document migration is required. Existing bundles may produce new ordering warnings;
normalize them with `okf lint --fix`, or set `frontmatter_order = "off"` in the applicable
bundle lint settings to disable that rule and its fixer. Ordinary concept writes still
normalize order. Ordering is an authoring convention, not an OKF conformance requirement.

The 0.4.3 plugins require a stable CLI `>=0.4.3, <0.5.0` so their frontmatter-fix guidance
matches CLI behavior. Update the CLI alongside the plugins. Cross-repository references
still require available local checkouts and valid authored paths; catalog IDs do not
clone repositories or rebase links.

## Validation

Release checks cover workspace tests with default and URL-source features, formatting,
release metadata, distribution scripts, generated references, and skill workflows.
Regression coverage includes recursive and idempotent ordering fixes, disabled rules,
configured ontologies, shared Git discovery and object reads, repeated source occurrences,
failed lookups, and fresh state between operations. GitHub Actions builds and tests the
four supported platform targets before publishing the release assets.

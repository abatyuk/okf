# OKF 0.4.4

This release fixes catalog-scoped linting, implements detailed outgoing relationship
inspection, and adds concept filtering to artifact inventories. The CLI and both
agent plugins are version 0.4.4; the OKF document specification remains v0.2.

## Changes

- Catalog orphan detection uses qualified graph identities, including cross-bundle
  ontology references. Incoming and outgoing references count toward connectivity;
  self-links and opaque artifact resources do not. Broken concept references remain
  visible to the graph and broken-link checks.
- `okf lint --fix` now applies frontmatter ordering fixes across the examined catalog
  scope. It locks affected bundles in a stable order, respects each bundle's ontology
  and lint settings, reloads changed concepts, and reports remaining findings. JSON
  fix records identify the bundle. The obsolete warning that lint fixes are not
  implemented has been removed.
- `okf links --details` now shows individual semantic relationship occurrences,
  including authored kind, source field, configured inverse label, attributes, and
  resolution status. Local JSON output emits outgoing relationship records and
  retains ordinary link records for targets not represented by semantic relationships.
  Catalog text output includes relationship details; catalog JSON retains its edge
  records. Default outgoing-link output remains unchanged.
- `okf artifact list --exclude-concepts` omits concepts while retaining opaque
  artifacts and reserved files. Combine it with `--directory .` to inventory the
  entire bundle; directory filtering and digest output remain available.
- Generated CLI references, retrieval and ontology guidance, and knowledge documents
  explain detailed outgoing links and the distinction between ordinary links and
  semantic relationship occurrences.

## Upgrade and compatibility

No document migration is required. The 0.4.4 plugins require a stable CLI
`>=0.4.4, <0.5.0` so their detailed-link guidance matches the installed CLI. Update
both together. Scripts using `links --details --json` must account for the newly
implemented relationship records; omit `--details` for the existing default format.

Catalog lint results may now correctly remove orphan findings for concepts connected
through qualified references. Catalog `lint --fix` now writes ordering repairs when
the rule is enabled; YAML comments and scalar presentation may normalize, as with
single-bundle fixes. Review changes through version control.

## Validation and platforms

Release validation covers workspace tests with default and URL-source features,
formatting, release metadata, distribution scripts, generated references, and skill
workflows. Regression tests cover catalog connectivity, scoped ordering fixes,
detailed outgoing relationships, and artifact filtering.

GitHub Actions tests and builds macOS (Apple Silicon and Intel) and Linux (ARM64 and
x86_64 musl) before publication. macOS release binaries require Developer ID signing
and Apple notarization. Release assets include platform archives, SHA-256 checksums,
and the standalone installer; Windows binaries are not provided.
